## 1. 무엇을, 왜 만드는가

### 의도
자기계발을 하고 싶은 사람은 많지만 의지와 끈기가 오래가지 않는다. 현실의 자기계발을 게임 캐릭터의 성장과 묶어서, **캐릭터가 크는 만큼 나도 크는** 재미와 성취감으로 꾸준함을 붙잡아 두는 게 목적이다.

### 이 프로젝트의 두 축
1. **게임**: 안드로이드 폰에서 쓰는 자기계발 성장 게임.
2. **루프 개발 구조**: 사용자가 코드를 짜거나 보지 않고, Claude Code가 사람 없이 반복해서 게임을 만들어 가는 구조. 참고 영상은 「바이브코딩도 귀찮은 직장인이 게임을 만드는 방법」(Road to $100K with AI Games, 2026-08-11)이다. 기획서를 읽고 → 기능 하나를 만들어 커밋하고 → 세션을 끝내고 → 할 일과 다음 할 일만 파일에 남기는 과정을 무한 반복한다.

### 사용자
- 게임 개발 경험이 없다. 코드를 보지 않는다.
- 사용자가 하는 일: 기획서 쓰기, 아이디어 던지기, 폰으로 직접 해 보고 한마디 피드백하기.
- 첫 목표는 **본인 폰에서 본인 혼자 매일 쓰는 것**이다. 스토어 출시는 지금 목표가 아니다.

## 2. 목표 · 비목표 · 실패 조건

### 목표
- 현실에서 자기계발 타이머를 켠 시간만 캐릭터 성장으로 이어지는 게임.
- 사용자가 자는 동안에도 게임이 만들어지고, 아침에 폰을 열면 반영되어 있는 개발 구조.
- 사용자가 `피드백.md`에 몇 줄 적으면 다음 루프에서 반영되는 흐름.

### 비목표 (첫 버전에서 하지 않음)
- 스토어 출시, 계정, 서버, 다른 사람과의 데이터 공유.
- 수동 전투 조작.
- 운동 중량·강도에 따른 보상 차등.
- 공부·독서 등 운동 외 활동 탭. 구조는 늘릴 수 있게 두되 화면에는 운동만 둔다.
- 완벽한 부정행위 방지. 타이머를 켜 두기만 하는 건 막지 못한다는 걸 받아들이고, 하루 인정 시간 상한만 둔다.

### 실패 조건 (동작은 해도 이렇게 되면 실패)
- 자기계발을 하지 않아도 게임 안에서 캐릭터가 강해질 수 있다.
- 몇 달 쌓은 기록이 사고로 날아가는데 복구할 방법이 없다.
- 루프가 밤새 돌았는데 게임이 깨져서 폰에서 열리지 않는다.
- 루프가 게임 폴더 밖의 파일을 건드린다.

## 3. 게임 규칙 (사용자와 확정한 것)

### 성장은 오직 현실에서만
- 활동 탭(첫 버전은 **운동**)을 누르면 타이머가 시작되고, **켜 둔 시간만큼 경험치**를 얻는다.
- 타이머는 시작 시각을 기록하고, 앱을 다시 열거나 멈출 때 지난 시간으로 계산한다. 화면을 꺼도, 브라우저가 백그라운드로 가도 시간이 정상적으로 쌓인다.
- 경험치가 차면 레벨이 오르고, 능력치를 올리거나 스킬을 배운다.

### 도전은 아무 때나
- 스테이지와 보스는 타이머와 관계없이 언제든 도전할 수 있다.
- 전투는 **자동**이다. 사용자는 결과를 보며 성장을 느낀다.
- 이기면 다음 스테이지가 열리고, 지면 "더 키워서 다시 오자"가 된다. 이것이 다시 현실의 자기계발로 돌아가게 만드는 핵심 흐름이다.

### 분위기
- **귀여운 캐주얼**: 둥근 마스코트, 파스텔 색, 같이 크는 친구 같은 느낌. 브레인스토밍 때 고른 시안 B 기준(`.superpowers/brainstorm/` 안의 `visual-style.html`). 화면 구성은 위에 레벨·경험치 바, 가운데 캐릭터와 몬스터가 있는 장면, 아래에 타이머 카드와 활동 탭.

## 4. 게임 규칙 (내가 정한 것 — 사용자가 이의 없음을 확인함)
- **전투는 경험치와 능력치를 주지 않는다.** 전투 보상은 스테이지 진행과, 캐릭터 꾸미기처럼 강해지지 않는 것들로 한정한다.
- **성장 구조**: 활동 시간은 두 가지를 준다. (1) 그 활동에 묶인 능력치가 **자동으로** 오른다(운동 → 힘·체력, 나중의 공부 → 지능 등). (2) 공통 경험치가 쌓여 레벨이 오르고, 레벨업마다 받는 포인트로 사용자가 **스킬을 골라** 배운다. 능력치를 사용자가 직접 분배하지는 않는다. 그래야 "운동을 해야 힘이 세진다"는 연결이 흐려지지 않는다.
- 활동별 하루 최대 인정 시간을 둔다(운동 기본 3시간, 기획서에서 조정).
- **저장 구조**: 원본은 활동 기록(언제, 무슨 활동, 몇 분)이다. 레벨·능력치는 이 기록에서 계산한다. 그래서 규칙이 바뀌어도 다시 계산할 수 있다. 다만 루프는 **기존 기록의 레벨·능력치가 내려가는 규칙 변경을 스스로 하지 않는다.** 그런 변경은 사용자가 `기획서.md`에 직접 적었을 때만 한다. 백업 파일은 이 활동 기록과 스킬 선택, 스테이지 진행, 꾸미기를 담는다.

| 항목 | 선택 | 이유 |

| 형태 | 웹 게임을 PWA로 만들어 폰 홈 화면에 설치 | AI가 브라우저에서 직접 띄워 보고 검사하기 가장 쉬워서 사람 없는 루프에 맞다. 업데이트도 다시 설치할 필요가 없다 |

| 그림 | 코드로 그리는 도형·SVG 위주 | 귀여운 캐주얼 스타일은 둥근 도형으로 표현하기 좋다. 이미지 생성 도구가 없어도 된다 |

| 백업 | 내보내기·가져오기(JSON 파일)를 **첫 마일스톤에 포함** | 브라우저 데이터가 지워지면 기록이 날아가는 약점을 막는다 |
| 자동 검사 | 규칙 테스트(Vitest) + 폰 크기 화면 검사(Playwright, 스크린샷을 AI가 직접 확인) | 사람이 안 봐도 깨졌는지 알 수 있어야 한다 |
| 호스팅 | GitHub Pages, 레포 `qkrrjs0811/game_creator` | 사용자 결정. 레포를 **공개로 전환**한다(현재 비공개, 비어 있음). 코드·기획서·피드백 기록이 공개된다는 점을 사용자가 알고 선택함 |
| 저장소 | `game_creator` 폴더에서 **새 git 저장소**를 시작하고 원격은 `qkrrjs0811/game_creator`만 쓴다 | 사용자 결정. 상위 `Geon_Project` 원격 레포는 삭제된 상태다. 로컬 상위 폴더의 git 기록은 건드리지 않는다 |

## 6. 루프 구조

### 0단계: 출발 준비 (사람이 지켜보는 세션에서 한 번)
빈 폴더에서는 루프가 헤매므로 먼저 아래를 만든다.
- 별도 git 저장소 생성, 원격 연결, 레포 공개 전환, GitHub Pages 배포(GitHub Actions) 설정.
- 최소 동작 버전: 화면 하나, 운동 타이머가 돌고 경험치가 쌓이는 것, 폰에 설치 가능한 것.
- 자동 검사 도구(Vitest, Playwright)와, 루프가 매 바퀴 돌리는 검사 명령 하나(예: `npm run check`).
- 루프용 파일 네 개와 루프 실행 스크립트(아래).
- 0단계가 끝나면 사용자가 폰에 실제로 설치해 보는 걸로 확인한다.

### 루프가 쓰는 파일
| 파일 | 주인 | 역할 |
|---|---|---|
| `기획서.md` | 사용자 | 게임이 어떤 모습이어야 하는지. 첫 버전은 이 설계 문서의 3~4장을 바탕으로 작성 |
| `할일.md` | 루프 | 만들 기능 목록. 위에서부터 하나씩 처리. 큰 일은 루프가 쪼개서 넣는다 |
| `진행기록.md` | 루프 | 바퀴마다 한 일, 검사 결과, 다음에 할 일. 루프의 기억 |
| `피드백.md` | 사용자 | 플레이 후 한마디. **사용자가 PC에서 직접 적는다**(사용자 결정). 루프가 **가장 먼저** 읽어 `할일.md` 맨 위로 옮기고, 처리한 항목은 "처리됨" 아래로 내린다. 사용자가 쓰는 중인 내용과 부딪치지 않도록, 루프는 바퀴 시작 때 한 번만 이 파일을 고치고 사용자가 쓴 문장은 고치지 않고 그대로 옮긴다(내 판단) |

### 한 바퀴
1. 실행 스크립트가 새 Claude Code 세션을 연다(`claude -p`, 고정된 루프 지시문 파일 사용). 이전 대화 기억은 없다.
2. 세션은 `피드백.md` → `진행기록.md` → `할일.md` → `기획서.md` 순으로 읽고 **할 일 하나**를 고른다.
3. 만든다 → `npm run check`(규칙 테스트 + 빌드 + 폰 크기 화면 검사)를 돌린다.
4. 통과하면 커밋한다. 통과하지 못하면 고쳐 보고, 그래도 안 되면 변경을 되돌리고 `진행기록.md`에 막힌 이유를 적는다. **깨진 상태로 커밋하지 않는다.**
5. `진행기록.md`를 갱신하고 세션을 끝낸다 → 1로.

### 할 일이 떨어졌을 때 (사용자 결정)
- **새 기능은 `기획서.md`에 적힌 것만** 만든다. 기획서에 없는 기능을 스스로 지어내지 않는다.
- 기획서의 기능을 다 만들었고 새 피드백도 없으면, 기획서 범위 안에서 버그 수정, 연출 다듬기, 검사 보강만 한다.
- 그것도 없으면 루프는 **스스로 멈추고** `진행기록.md`에 "할 일이 없어 멈췄음"과 사용자에게 제안할 아이디어를 적는다. 제안은 만들지 않고 적기만 한다.

### 실행 스크립트의 안전장치
- 폴더에 `STOP` 파일이 있으면 지금 바퀴까지만 하고 멈춘다.
- **사용량 규칙 (사용자 결정)**: 루프는 시간대 제한 없이 돌 수 있고, **주간 한도의 10%만 남기고** 나머지는 다 써도 된다. 주간 사용량이 90%에 닿으면 루프는 멈추고 이유를 기록한다. 사용자가 자기 작업에 사용량이 필요할 땐 말하겠다고 했고, 그때는 `STOP` 파일로 멈춘다.
  - 몇 시간 단위 한도에 걸리면 한도가 풀릴 때까지 기다렸다가 이어서 돈다.
  - **빌더가 먼저 확인할 것**: 스크립트가 주간 사용량 비율을 읽을 수 있는 확실한 방법(예: Claude Code가 제공하는 사용량 정보). 확실한 방법이 없으면 루프를 돌리기 전에 사용자에게 알리고, 대안(하룻밤 바퀴 수 상한 등)을 정한다. 짐작으로 돌리지 않는다.
  - 사용자는 Max 요금제이고 Pro로 내릴 수 있으므로, 같은 규칙이 Pro에서도 그대로 동작해야 한다.
- 반복 작업은 **Opus 5.5**(`claude-opus-5-5`)로 돌린다(사용자 결정). 스크립트 설정 한 줄로 바꿀 수 있게 한다.
- 권한은 게임 폴더 안의 파일 수정과 정해진 명령(npm, git 커밋 등)으로만 묶는다. `--dangerously-skip-permissions`는 쓰지 않는다.
- 원격 푸시(곧 폰 반영)는 검사를 통과한 커밋만, **한 시간에 한 번 이하**로 한다.
- 실행 기록(바퀴별 시작·끝·결과)을 파일로 남겨, 아침에 무슨 일이 있었는지 볼 수 있게 한다.

### 사용자의 하루
- 컴퓨터를 켜 두고 루프 실행(주로 밤, 시간대 제한은 없음).
- 폰에서 게임을 열어(자동 반영) 해 보고, PC에서 `피드백.md`에 몇 줄 적기.
- 가끔: `기획서.md` 고치기.

## 7. 첫 마일스톤 (M1: 매일 쓸 수 있는 최소 게임)
- 운동 타이머 → 힘·체력 자동 상승 + 경험치 → 레벨업 → 스킬 선택.
- 하루 인정 시간 상한.
- 스테이지 여러 개와 보스 하나, 자동 전투, 승패 결과.
- 귀여운 캐주얼 스타일의 캐릭터·몬스터·화면.
- 백업 내보내기·가져오기.
- 폰 홈 화면 설치, 오프라인에서도 열림.

M1 이후의 순서는 루프가 `기획서.md`와 `피드백.md`를 보고 정한다.
